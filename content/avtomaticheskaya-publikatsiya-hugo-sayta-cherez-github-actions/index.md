# Автоматическая публикация Hugo-сайта через GitHub Actions: современный подход

При работе с Hugo у разработчика есть два типа файлов:

- **исходный проект сайта** — файлы, которые мы создаём и изменяем;
- **сгенерированный статический сайт** — готовые HTML, CSS и JavaScript-файлы, которые публикуются для посетителей.

Один из главных вопросов при работе с Hugo:

> Нужно ли хранить папку `public/` в GitHub?

Современный подход — хранить только исходный проект Hugo, а генерацию и публикацию сайта полностью автоматизировать через GitHub Actions.

---

# Как работает автоматическая публикация

После настройки процесс выглядит так:

```

Изменения в Hugo-проекте
↓
git push
↓
GitHub Actions запускает сборку
↓
Hugo создаёт статический сайт
↓
Результат публикуется через GitHub Pages
↓
Сайт обновляется автоматически

```

Разработчику больше не нужно вручную запускать генерацию сайта и загружать папку `public/`.

---

# Структура проекта

В GitHub хранится только исходный Hugo-проект:

```

mysite/

├── archetypes/
├── assets/
├── content/
├── data/
├── layouts/
├── static/
├── themes/
│
├── hugo.toml
├── package.json
│
└── .github/
└── workflows/

```

Папка:

```

public/

```

не добавляется в репозиторий.

Она создаётся автоматически во время процесса сборки.

---

# Почему не нужно хранить public/

Папка `public/` — это результат работы Hugo, а не исходный код.

Она похожа на:

- `node_modules` в проектах Node.js;
- скомпилированные файлы CSS и JavaScript;
- временные файлы сборки.

Если удалить `public/`, сайт можно снова создать командой:

```

hugo

```

Поэтому хранить её в Git обычно не требуется.

# Настройка .gitignore

В корне проекта создайте файл:

```

.gitignore

````

Добавьте:

```gitignore
/public/
/resources/
.hugo_build.lock
.DS_Store
````

Теперь Git будет игнорировать автоматически создаваемые файлы.

---

# Загрузка Hugo-проекта в GitHub

Создайте новый репозиторий, например:

```
github.com/user/mysite
```

После этого отправьте проект:

```bash
git add .

git commit -m "Initial Hugo website"

git push
```

Теперь GitHub хранит только исходный код сайта.

---

# Настройка GitHub Actions

GitHub уже имеет готовые шаблоны автоматизации для популярных технологий, включая Hugo.

Чтобы создать workflow:

1. Откройте вкладку:

```
Actions
```

2. Нажмите:

```
New workflow
```

3. Найдите шаблон:

```
Hugo
```

4. Выберите готовый workflow для Hugo сайта.

5. Нажмите:

```
Configure
```

6. Сохраните созданный workflow.

GitHub автоматически создаст файл настройки внутри:

```
.github/workflows/
```

Использование готового шаблона предпочтительнее, потому что GitHub может обновлять рекомендуемые настройки и версии инструментов.

---

# Настройка GitHub Pages

Откройте:

```
Repository
→ Settings
→ Pages
```

В разделе источника публикации выберите:

```
GitHub Actions
```

Теперь GitHub Pages будет получать готовую версию сайта после успешной сборки.

---

# Настройка собственного домена

Если вы используете собственный домен:

Например:

```
blog.example.com
```

создайте файл:

```
static/CNAME
```

Внутри укажите:

```
blog.example.com
```

При сборке Hugo автоматически перенесёт этот файл в готовый сайт.

---

# Ежедневный процесс работы

После настройки публикация становится простой.

Создайте новый пост:

```
content/blog/my-post.md
```

или измените дизайн:

```
layouts/
assets/
static/
```

Проверьте сайт локально:

```bash
hugo server
```

После изменений:

```bash
git add .

git commit -m "Update website"

git push
```

После отправки изменений:

1. GitHub Actions автоматически запускает Hugo.
2. Hugo создаёт новую версию сайта.
3. GitHub Pages публикует обновления.

Обычно обновление занимает меньше нескольких минут.

      |

GitHub Actions

GitHub Pages

      |
      |
Посетители сайта

✅ Исходный код хранится отдельно от готового результата
✅ История изменений остаётся чистой
✅ Публикация происходит автоматически
✅ Сайт легко восстановить на новом компьютере
✅ Подходит для блогов, документации и корпоративных сайтов

Hugo + GitHub Actions + GitHub Pages — это простой и современный способ автоматической публикации статических сайтов.
